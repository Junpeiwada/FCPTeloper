## 検証可能性の方針（Claude 単独で動作確認できること）

ユーザーが UI を触らないと不具合に気づけない状態を避けるため、**全ての主要機能を Claude が Bash から単体実行・検証できる形で実装する**。

### 原則
- **CLI ファースト**: 機能を実装する際は、UI ボタンより先に CLI エントリを用意する。UI はその CLI と同じ main プロセス関数を呼び出す薄いラッパーに留める。
- **UI E2E は当面やらない**: Electron UI 自体の自動テストは初版スコープ外。ロジックは CLI / ユニット層でカバーする。
- **副作用の分離**: FCPXML 生成・JSON パース・セグメント処理など純粋ロジックは Electron 依存なしの関数として切り出し、CLI からも UI からも呼べるようにする。
- **構造化ログ**: main プロセスの IPC・Python サブプロセス・Claude 呼び出しは JSON 行ログを既定の場所（`~/Library/Logs/FCPTeloper/`）に追記し、Claude が `tail` で追跡できるようにする。
- **共通フェーズ完了基準**: 各フェーズの実装機能は `npm run …` の組み合わせのみ（UI 起動なし）で E2E 確認できること。

### CLI コマンド一覧（フェーズ進行に伴い拡充）

命名規則: `<namespace>:<verb>` で統一。

| コマンド | 役割 | 用意するフェーズ |
|---|---|---|
| `npm run sdk:smoke` | Claude SDK Max 枠の疎通確認（標準出力に応答テキスト） | フェーズ 1 |
| `npm run transcript:generate -- <video>` | 1 動画を文字起こし、§6 JSON を出力 | フェーズ 2 |
| `npm run transcript:generate -- --batch <dir>` | フォルダ内動画をバッチ処理 | フェーズ 6 |
| `npm run transcript:validate -- <transcript.json>` | §6 スキーマ準拠チェック | フェーズ 2 |
| `npm run video:probe -- <video>` | FFprobe メタデータ（`recorded_at`, `fps`, `duration`）を JSON 出力 | フェーズ 4 |
| `npm run fcpxml:build -- <transcript.json>... -o <out.fcpxml>` | 新規モード FCPXML 生成 | フェーズ 4 |
| `npm run fcpxml:extend -- <in.fcpxml> <transcript.json>... -o <out.fcpxml>` | 既存拡張モード FCPXML 生成 | フェーズ 6 |
| `npm run ai:format -- <transcript.json> --segment <id>` | セグメント整形 (id は §6 `segments[].id`) | フェーズ 5 |
| `npm run ai:shorten -- <transcript.json> --segment <id>` | テロップ短縮 (id は §6 `segments[].id`) | フェーズ 6 |
| `npm run ai:suggest -- <transcript.json>` | 全体提案を `ai_suggestions[]` に書き込み | フェーズ 6 |
| `npm run logs:tail` | 構造化ログを tail（Claude が動作中の挙動を観察するため） | フェーズ 3 |

| `existing_multicam.fcpxml` | マルチカム含む（非対応警告テスト用） | フェーズ 6 |

**ASR 出力の非決定性への対応**:
- Whisper の出力はモデルバージョン・乱数・GPU/CPU 差で揺れる。期待 JSON との完全一致 diff は不安定なので、**比較対象は構造項目に限定**する。
  - チェックする項目: フィールドの存在・型、`segments` 件数の妥当性、`recorded_at` / `recorded_at_source` / `fps` / `video_duration_sec` の値、`text` 不変保証、`language` の存在
  - チェックしない項目: ASR 出力テキストの完全一致、`start`/`end` の小数点以下完全一致
- FCPXML 出力は固定入力 JSON から決定的に作れるため、**スナップショット完全一致比較を採用**する（属性順揺れの吸収のため DOM 比較ハーネスを推奨、後述 #suggestion）。

## 進捗管理ルール

### ステータス定義
- 🔲 **未着手** (Todo): 未開始
- 🟡 **進行中** (Doing): 着手済み・作業中
- 🔴 **ブロック** (Blocked): 依存・問題で停止中（理由を併記）
- ✅ **完了** (Done): 受け入れ条件を満たし完了

### 運用ルール
1. **フェーズ開始時**:
   - 該当フェーズの「詳細タスク」を再点検し、最新状況に合わせて追加・分解・削除する
   - ステータス表のステータスを 🟡 に更新、開始日を記入
2. **タスク完了時**:
   - チェックボックスにチェック (`[x]`)、`完了` を付与
   - 仕様書からの差分・逸脱があれば後述の「§ 仕様逸脱ログ」に追記
   - **依存関係のある複数タスクを 1 セッション内で連続実装した場合は、まとめて更新してよい**。ただしフェーズをまたぐ場合は必ず分割する。
3. **フェーズ完了時**:
   - 受け入れ条件をすべて満たしたらステータス表を ✅ に更新、完了日を記入
   - 仕様書との差分があれば仕様書本体への反映可否を検討（反映する場合は仕様書を更新してその旨を逸脱ログに記載）

### 仕様逸脱ログ
仕様書（[仕様.md](仕様.md)）との差分・スコープ変更を記録する。フェーズ単位でセクション末尾に追記し、最後に [§ 全体の仕様逸脱ログ](#全体の仕様逸脱ログフェーズ横断) に集約する。

## フェーズ 3: Electron Forge 雛形

**目的**: 開発・パッケージング基盤を立ち上げ、構造化ログ基盤を整える。
**仕様参照**: §4.1.1, §9 (ディレクトリ構成)

### 既存ファイル保護方針

`npm init electron-app` は空ディレクトリでないと既存ファイルを上書きする可能性があるため、以下の手順を採用する：

1. 一時ディレクトリ（例: `/tmp/fcpteloper-skeleton`）で雛形を生成
2. `rsync --ignore-existing` で本リポジトリにマージ（`Docs/` `.git` は触らない）
3. `git status` で `Docs/仕様.md` と `Docs/実装計画.md` が無傷であることを確認
4. 失敗時は `git reset --hard HEAD` で復旧

  - 雛形の `forge.env.d.ts` を tsconfig の include に入れないと `MAIN_WINDOW_VITE_DEV_SERVER_URL` 等の型エラーが出る
  - `package.json` の `"type": "module"` を消してCJS既定にした (Forge + electron-squirrel-startup が CJS なため)
  - 構造化ログは `redactPii()` で再帰的に `text`/`telop_text` を長さに置換する設計。配列内のオブジェクトにも適用
- 課題:
  - `npm start` の React 描画はまだユーザー確認待ち
  - フェーズ4b で main プロセス用のロガーを Electron `app.getPath('logs')` 経由に切り替えるか検討 (現状は homedir 直書きでも macOS 用パスと一致)
