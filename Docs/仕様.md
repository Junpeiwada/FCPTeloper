# FCPTeloper 仕様書

複数動画の文字起こしを **Electron アプリでレビュー・AI修正** し、Final Cut Pro 向けの FCPXML を生成するパイプライン。

## 1. ゴール

複数の動画ファイルを一括処理して、

1. 各動画ごとの中間 JSON（文字起こし結果）を生成
2. **Electron アプリ**で動画プレビューしながら JSON をレビュー・編集
3. **Claude Code (Max 枠)** で AI 修正（テロップ向け整形・フィラー除去・要不要判断）
4. 最終的に喋っている部分だけ残し、テロップ付きのタイムラインを持つ FCPXML を出力
5. Final Cut Pro に読み込み、人間が最終調整

**動作モードは2つ:**
- **新規モード**: フォルダ内動画を撮影日時順に並べて新タイムラインを構築
- **既存プロジェクト拡張モード**: ユーザーが整えた FCP プロジェクト (FCPXML) を読み込み、既存のカット・順番を保ったままテロップだけ後乗せ

## 2. 設計方針

- **完全ローカル・無料**で文字起こしを行う（クラウド ASR 不使用）
- **日英混在に対応**: Whisper の言語自動検出を使い、セグメント単位で日本語/英語を判別して書き起こす（話者は日本語話者だが、相手が英語を喋るケースを想定）
- **AI 修正は Claude Code (Max 枠) で API 課金ゼロ**
- **中間 JSON を必ず挟む**: 文字起こし結果を JSON で人間 (+AI) が確認・編集してから FCPXML を生成する 3 段階構成
- **FCP 本体は操作しない**: FCPXML を生成して FCP で読み込ませる方式（AppleScript は FCP のタイムライン操作能力が限定的のため不採用）
- **既存資産を尊重**: `~/Documents/Project/AISandbox/VideoToText/` の Whisper + pyannote 実装をバックエンドとして再利用、AgentNest の Claude Code SDK 呼び出しパターンを流用

## 4. アーキテクチャ

### 4.1 技術スタック

| 層 | 技術 | 理由 |
|---|---|---|
| デスクトップ | **Electron** | 動画プレビュー・ローカルファイル・サブプロセス起動が容易 |
| プロジェクト雛形 / ビルド / パッケージング | **Electron Forge** (公式) | `npm init electron-app` で雛形生成。開発・パッケージング・配布が一貫した CLI で完結。Webpack/Vite テンプレートも公式提供 |
| Forge テンプレート | `vite-typescript` テンプレート | TypeScript + Vite (renderer) を最初から含む構成。Electron Forge 公式テンプレート |
| UI 言語 | **TypeScript + React** | 型安全、コンポーネント分割しやすい |
| 文字起こしバックエンド | **Python (既存 VideoToText/)** | Whisper + pyannote の実績資産を流用。**言語指定は外して自動検出** に変更（既存 `transcribe.py` は `language="ja"` 固定なので、本プロジェクト用ラッパー `python/transcribe_to_json.py` で上書き） |
| AI 修正 | **Claude Agent SDK + Claude Code preset** | Max 枠認証で API 課金不要 |
| FCPXML 生成 | TypeScript (Electron main) | 外部スクリプト起動を減らし、シンプルに |

## 5. Claude Code SDK 連携の要点（重要）

Electron Main プロセスから Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`) を呼び出す。**Max プラン (OAuth) の枠を消費**するために以下の指定が必須：

```typescript
import { query } from "@anthropic-ai/claude-agent-sdk";

const stream = query({
  prompt: userPrompt,
  options: {
    cwd: process.cwd(),
    systemPrompt: { type: "preset", preset: "claude_code" },  // ★ Max枠認証の鍵
    settingSources: ["user"],                                  // ★ ~/.claude を参照
    permissionMode: "default",
    // ツール使用は基本不要なので canUseTool で全否定 or disallowedTools 指定
  },
});

let resultText = "";
for await (const msg of stream) {
  if (msg.type === "result" && "result" in msg && msg.result) {
    resultText = msg.result;
  }
}
```

**重要事項:**

- `systemPrompt: { type: "preset", preset: "claude_code" }` と `settingSources` 指定により、SDK は内部で Claude Code CLI と同じ認証経路（`~/.claude` 配下の OAuth トークン）を使う。**`ANTHROPIC_API_KEY` 環境変数は不要**。
- 参考実装: `~/Documents/Project/AgentNest/server/claude/executor.ts` の `runQuery` 関数。
- レート制限はユーザーの Claude Max プラン枠で消費される。`onLimitError` 相当のハンドリングを入れること（AgentNest の `isLimitErrorText` 参照）。
- ツール使用は不要（テキスト変換タスクなので）。`canUseTool` で全 deny するか、prompt 内で「ツール使用しない」と明示。

### 5.1 AI 修正の機能セット

| 機能 | プロンプト概要 | 入力 | 出力 |
|---|---|---|---|
| **セグメント整形** | 「以下のセリフを意味を変えずに整え、`telop_text` にして」 | 1セグメントの `text` | 整えたテキスト → `telop_text` に格納 |
| **テロップ短縮** | 「以下を 20 字以内のテロップ風に要約して」 | 1セグメントの `text` | 短縮テキスト → `telop_text` に格納 |
| **動画全体提案** | 「以下の全文字起こしを読み、不要部分・言い直し・重複を JSON で指摘して」 | 動画全体の `segments[]` | 提案 JSON（適用前にユーザー確認） |

## 6. 中間 JSON 仕様

ファイル名: `<video名>.transcript.json`、動画ファイルと同じディレクトリ or 専用 `transcripts/` ディレクトリに配置。

```json
{
  "version": "1.1",
  "source_video": "/abs/path/to/clip1.mp4",
  "video_duration_sec": 123.45,
  "recorded_at": "2025-10-01T11:07:00Z",
  "recorded_at_source": "mp4_creation_time",
  "asr_engine": "whisper-large-v3",
  "asr_engine_version": "20250101",
  "fps": 30,
  "created_at": "2026-05-11T10:30:00+09:00",
  "segments": [
    {
      "id": 0,
      "start": 1.20,
      "end": 4.50,
      "text": "こんにちは、今日はテストです。",
      "language": "ja",
      "speaker": "SPEAKER_00",
      "use": true,
      "telop_text": null,
      "ai_edited": false
    },
    {
      "id": 1,
      "start": 4.50,
      "end": 6.00,
      "text": "Nice to meet you.",
      "language": "en",
      "speaker": "SPEAKER_01",
      "use": true,
      "telop_text": null,
      "ai_edited": false
    }
  ],
  "ai_suggestions": []
}
```

| フィールド | 型 | 説明 |
|---|---|---|
| `version` | string | スキーマバージョン |
| `source_video` | string | 動画ファイル絶対パス |
| `video_duration_sec` | number | 動画全体の長さ（秒） |
| `recorded_at` | string\|null | **撮影日時 (ISO8601)**。新規モードでのタイムライン並び順に使用 |
| `recorded_at_source` | string | `mp4_creation_time` / `finder_creation_date` / `unknown` のいずれか |
| `asr_engine` | string | 使用 ASR エンジン名 |
| `asr_engine_version` | string | エンジンのバージョン文字列（履歴用） |
| `fps` | number | 動画フレームレート |
| `created_at` | string | ISO8601 タイムスタンプ |
| `segments[].id` | int | 連番 |
| `segments[].start` | number | 開始秒（小数2桁） |
| `segments[].end` | number | 終了秒（小数2桁） |
| `segments[].text` | string | ASR 生テキスト（**不変、編集禁止**） |
| `segments[].language` | string\|null | Whisper が検出した言語コード (`ja` / `en` 等)。AI 修正のプロンプト分岐や UI バッジ表示に使う |
| `segments[].speaker` | string\|null | 話者ID（**内部メタのみ。FCPXML には反映しない**。AI 修正時の文脈情報や UI 一覧表示に使う） |
| `segments[].use` | bool | タイムラインに含めるか（デフォルト true） |
| `segments[].telop_text` | string\|null | テロップ表示文字列。null なら `text` を使う |
| `segments[].ai_edited` | bool | AI が編集したか（履歴管理用） |
| `ai_suggestions` | array | AI 全体提案のドラフト保存場所（未適用） |

**設計原則:**
- `text` は ASR の生出力で、**人間も AI も編集してはいけない**（後で再 ASR せずに比較できるようにするため）
- 編集は `telop_text` と `use` フラグで行う

### 7.3 永続化

- transcript.json は動画と同じディレクトリに保存
- 編集は逐次（debounce 500ms）でファイルに書き戻す（ロスト防止）
- アプリ設定（最近開いたフォルダ等）は `app.getPath('userData')` 下の `settings.json`

## 8. FCPXML 生成仕様

### 8.0 動作モード

| モード | 入力 | 並び順 | 既存編集 |
|---|---|---|---|
| **新規モード** | 動画フォルダ | **撮影日時 (`creation_time`) 昇順** | なし、一から構築 |
| **既存プロジェクト拡張モード** | 既存 `.fcpxml` + 動画 | 既存タイムラインの順序を維持 | 保持、テロップだけ後乗せ |

### 8.1 撮影日時の取得（新規モード）

並び順のソースは **MP4 内部の `creation_time` (mvhd) を優先**。FFprobe で取得:

```bash
ffprobe -v quiet -show_entries format_tags=creation_time \
        -of default=nw=1:nk=1 video.mp4
# 出力例: 2025-10-01T11:07:00.000000Z
```

実装方針:

- `creation_time` が取得できない動画は、フォールバックとして `mdls -name kMDItemContentCreationDate` (Finder 作成日時) を使う
- 両方失敗したら**並び順未定 (UIで警告表示)** とし、ユーザーに手動順序付けを促す
- 取得した日時は `transcript.json` の新フィールド `recorded_at` (ISO8601) として保存（再取得不要に）

**注意**: 全機種（DJI/Sony/GoPro 等）は `creation_time` をローカル時刻として UTC タグ付きで記録する慣習がある（`~/Documents/Project/AISandbox/MP4Date/` の知見参照）。ソート目的なら絶対時刻の正確性は気にせず、文字列比較で十分。

### 8.2 既存 FCPXML の読み込み（既存プロジェクト拡張モード）

#### 8.2.1 入力取得

ユーザーが Final Cut Pro で:

1. プロジェクトを選択
2. ファイル > 書き出す > XML... (FCPXML 1.11)
3. 出力された `.fcpxml` を本アプリにドラッグ&ドロップ

#### 8.2.2 解析・処理フロー

```
1. .fcpxml を XML パース
2. <resources> セクションから全 <asset> (src 動画パス) を抽出
3. <spine> 配下の <asset-clip> を順に走査:
   - 各クリップの src 動画パス
   - タイムライン上の offset, start, duration を記録
   - これがタイムライン上の「使用区間」
4. 各動画について transcript.json を探す:
   - 既にあれば読み込み
   - なければ Whisper で文字起こし
5. 「使用区間」と「セグメント」を重ね合わせる:
   - クリップが使っている時間範囲に含まれるセグメントだけを抽出
   - そのセグメントの telop_text (or text) を <title> 要素として
     タイムラインの当該位置に重ねる
6. 元の <asset-clip> は一切変更しない (カット位置・順序を維持)
7. <title> 要素だけを追加した新しい .fcpxml を出力
```

#### 8.2.3 出力

- ファイル名: `<元プロジェクト名>_with_telop.fcpxml`
- ユーザーは FCP で「ファイル > 読み込む > XML」して**新規プロジェクト**として開く（既存への上書きは FCP の仕様上不可）
- 元プロジェクトは無傷で残る

#### 8.2.4 制約

- 既存タイムラインに**既にテロップがある場合**: 上書きせず、追加レーンに積む。FCP 上で不要なら削除してもらう
- マルチカム・複合クリップ (`<mc-clip>` / `<ref-clip>`): 初版では非対応、警告して該当部分はスキップ
- スピード変更 (`<conform-rate>` `<timeMap>`): 初版では非対応、警告
- トランジション (`<transition>`): 跨ぐ箇所のテロップは挿入しない

### 8.3 タイムライン構築（新規モード）

- 動画 JSON 群を `recorded_at` 昇順で結合して 1 つのタイムラインに並べる
- 各動画の `use: true` のセグメントだけを順番に並べる
- ビデオクリップ: 元動画の `start`〜`end` 範囲を切り出して配置
- 音声: ビデオクリップに同期したまま含める
- タイトル: 同じ時間範囲に重ねて `telop_text` (or `text`) を表示
- セグメント間のギャップは詰める（J/L カット・無音バッファは FCP 上で手動調整）

### 8.4 テロップのデザイン（単一固定）

スタイルバリエーションは持たない。**全テロップで以下の固定スタイルを使う**。将来変更したくなったら本仕様を書き換えて再ビルドする方針（設定 UI は作らない）。

| 項目 | 値 |
|---|---|
| フォント | Hiragino Sans W6 |
| サイズ | 60pt（1080p基準、解像度に応じてスケール） |
| 色 | 白 (#FFFFFF) |
| 縁取り | 黒 (#000000)、太さ 4px |
| 位置 | 画面下から 15% |
| 改行 | 全角 18 文字で自動改行 |
| 話者ごとの色分け | **しない**（全話者同色） |
| 話者名の表示 | **しない**（speaker フィールドは内部メタとしてのみ保持） |

FCP 標準の "Basic Title" エフェクトを使用。FCP 上で個別調整したい箇所はインポート後に手動編集する。

### 8.5 FCPXML バージョン

`fcpxml version="1.11"`（FCP 10.6.x 以降）。古い FCP 対応が必要なら 1.10 にダウングレード。

### 8.6 タイムコード

- フレームレートは動画から FFprobe で取得
- 秒→フレーム変換は `round(秒 × fps)`
- ドロップフレーム非対応（30/60fps 整数 FPS のみ。29.97fps は要対応検討）

### 8.7 メディア参照（動画は外部参照固定）

- 元動画は **絶対パス参照**で `<asset>` を作る
- **動画ファイルはコピー・移動・FCP ライブラリ取り込みをしない**（外部参照のまま使う）
- 動画は別ディスク・別ディレクトリのどこにあってもよい。アプリは元の場所を参照し続ける
- ユーザーが動画を移動するとリンク切れになるが、これは仕様として許容（再リンクは FCP の標準機能で対応してもらう）
- ライブラリ相対パスや Consolidate Media、Optimized Media 生成は対象外

## 11. 制約・既知の課題

- **FCP のバージョン依存**: FCPXML 1.11 は FCP 10.6.x 以降
- **ドロップフレーム**: 29.97/59.94fps は初版非対応
- **話者分離の精度**: 重なって喋ると話者IDが揺れる
- **言語自動検出の精度**: Whisper はセグメント単位で言語を判定するが、極端に短い相槌（「うん」「yeah」など）は誤判定する可能性あり。UI 上で `language` を表示し、必要なら手動で `telop_text` を直す運用
- **AI 修正のレート**: Claude Max 枠を消費。長い動画の全体提案はトークン多めなので注意
- **AI 修正の品質保証**: 必ず `telop_text` 経由で人間が確認できる形にする（`text` は不変）
- **複数動画の音声レベル**: 連結時にゲイン差が出る可能性、FCP 上で手動調整
- **Electron バンドルサイズ**: Claude Agent SDK + Python ランタイム呼び出しで大きくなる。Python は外部依存とし、バンドルしない
- **既存 FCPXML 拡張モードの非対応要素**: マルチカム・複合クリップ・スピード変更・トランジション跨ぎ箇所のテロップ挿入（§8.2.4 参照）
- **既存 FCP プロジェクトへの直接上書き不可**: FCP の仕様上、出力は常に新規プロジェクトとして読み込まれる。元プロジェクトは無傷で残る
- **`creation_time` のフォーマット差**: 機種により `Z` 終わり (UTC) と +09:00 形式の混在あり。ソート時は ISO8601 標準パーサーで吸収する
- **撮影日時欠落動画**: `creation_time` も Finder 作成日時も取れない場合、ファイル名順 → ユーザー手動並び替えにフォールバック

## 12. PoC の進め方（推奨手順）

1. **AgentNest の executor.ts を読み込み**、Claude SDK の Max 枠呼び出しパターンを最小サンプルに切り出す
2. **VideoToText/ の JSON 出力モード追加** (前段の本ファイル §4 ギャップ表参照)
3. **Electron Forge 雛形作成**:
   ```bash
   cd ~/Documents/Project/FCPTeloper
   npm init electron-app@latest . -- --template=vite-typescript
   ```
   既存の `Docs/` `.git` を保ったまま生成されることを確認（必要なら別ディレクトリで生成してマージ）
4. **サンプル動画 1 本** で「文字起こし → JSON 表示 → use 切替 → FCPXML 生成 → FCP 読み込み」の最小フロー確認
5. **AI 修正 1 機能（セグメント整形）** だけ追加して動作確認
6. **バッチ処理 / 残り AI 機能 / UI 改善** を順次追加

## 13. やらないこと（スコープ外）

- カット間の自動クロスフェード
- **テロップスタイルの選択肢提供**（単一固定、§8.4 参照）
- **話者ごとのテロップ色分け・話者名表示**（speaker は内部メタとしてのみ保持）
- **動画ファイルのコピー・移動・ライブラリ取り込み**（外部参照固定、§8.7 参照）
- BGM / 効果音の自動挿入
- マルチカム編集
- カラーグレーディング自動付与
- Premiere Pro / DaVinci Resolve 向け XML 出力（FCP 専用）
- ASR 自体の改良（kotoba-whisper 等への乗り換えは将来課題）
- クラウド ASR / クラウド ファイル ストレージ連携
